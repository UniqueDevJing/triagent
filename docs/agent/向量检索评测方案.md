# T-A 向量检索腿：评测方案与启用流程

> 配套代码：`HybridKnowledgeRetriever` / `InMemoryVectorKnowledgeRetriever` / `DashScopeEmbeddingClient`（health-admin rag 包）+ `EmbeddingClient` / `Cosine` / `RrfFuser`（agent-core rag 包）。

## 现状与原则

RAG 此前只有 `KeywordKnowledgeRetriever`（MySQL 关键词/词频检索）。向量腿已实现但**默认关闭**
（`assistant.vector-rag.enabled=false`）——沿用全项目一贯的可证伪原则：
**增强腿必须先证明增量，才配长期开启。** 证明不了，接口本身就是答案。

## 架构

```
用户主诉 ──┬─→ KeywordKnowledgeRetriever（MySQL bigram OR-LIKE，现有）
           │
           └─→ InMemoryVectorKnowledgeRetriever（全量文档嵌入缓存 + 余弦排序）
                    └─ DashScopeEmbeddingClient（text-embedding-v3, 1024 维）
两腿 → RrfFuser（RRF k=60，只看排名免量纲校准）→ HybridKnowledgeRetriever（@Primary）
```

降级链（RAG 可用性永远优先）：

- 开关关闭 → 两个新 Bean 不加载，行为与改造前**逐字节一致**
- 嵌入 API key 缺失 / 调用失败 / 全量嵌入失败 → 向量腿标记不可用，**长期降级纯关键词**（只告警一次）
- 单次查询嵌入失败 → 该次返回空向量腿，融合自动退化为关键词结果

机制级验证：no-Maven javac harness **14/14**（余弦数学性质 / 同义不同词的向量腿命中 /
关键词词面下界必漏 / RRF 去重融合与 topK / 嵌入失败降级 / 空腿边界），脚本化假嵌入模型驱动。

## 部署环境启用流程（沙箱外执行）

1. **建 mini 评测集**（30~50 问）：从知识库抽样，每问标注期望命中的疾病/文章 ID。
   刻意包含两类：
   - **词面正交问题**（如"胸口闷痛像压了石头"→ 期望命中"急性心肌梗死"）——这是向量腿的预期增量区；
   - **词面直配问题**（如"腰痛伴下肢放射痛"）——两类腿都该命中（防向量腿拖后腿）。
2. **跑对照**（环境变量 `ASSISTANT_VECTOR_RAG_ENABLED=true/false` 各一遍）：
   统计 Recall@3 与 MRR，分开报"词面正交子集"与"词面直配子集"。
3. **判定规则**（写死，不拍脑袋）：
   - 词面正交子集 Recall@3 增量 > 10pp 且词面直配子集无回退 → 保持 `enabled=true`；
   - 否则关闭开关，向量腿以代码形式保留待语料增长后再评。

## 口径边界（诚实声明）

- 内存全量余弦检索适用上限约万条文档；超过应换 pgvector/Milvus（仅替换
  `InMemoryVectorKnowledgeRetriever` 一个类）。
- 本沙箱无嵌入 API 与 MySQL 实例，harness 用脚本化假嵌入验证**机制**；真实增量数字
  必须来自部署环境——文档不虚构数字。
- RRF 免校准换来的是"只信排名"：两腿分数不参与融合排序，如需分数级融合须先做归一化校准。

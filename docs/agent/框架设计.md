# 基于 LLM 的多 Agent 分诊就医系统 — 项目框架设计

> 项目正式名称：**基于 LLM 的多 Agent 分诊就医系统**（对外产品名：智能医疗系统）。
> 基于现有 health-admin 多模块（Spring Boot 3.2 + Sa-Token + DeepSeek）的改造设计。
> 设计原则：**复用优先**——复用现有工具层、mapper、Sa-Token、SseEmitterHolder，仅新增"进程内 Agent 编排层"。

## 1. 现状资产（直接复用，不重写）

| 资产 | 位置 | 复用方式 |
|------|------|---------|
| 工具端点（会员/疾病/预约/知识库查询） | `health-admin/.../controller/agent/AgentController` | 其底层 mapper 查询逻辑沉淀为 Spring AI `@Tool` |
| LLM 配置（DeepSeek） | `health-framework/.../intelligent/LlmConfig` + `application.yml` 的 `llm.*` | 新增 `spring.ai.openai.*` 读同一环境变量（`LLM_API_KEY` 等） |
| SSE 基础设施 | `health-framework/.../realtime/SseEmitterHolder` | 聊天端点沿用 `SseEmitter` + `event(name,data)` 协议 |
| 统一响应/异常 | `com.health.common.core.AjaxResult` + `GlobalExceptionHandler` | Controller 直接返回 `AjaxResult`，异常走全局处理 |
| 鉴权 | Sa-Token（`StpUtil`） | 前端聊天端点要求登录态；Coze 工具端点保留 `X-Agent-Key` |
| 业务实体/Mapper | `health-system` | 工具层直接注入 Mapper |

## 2. 新增包结构（位于 health-admin 内，符合 CLAUDE.md「新代码放 health-admin」约定）

```
com.health.web.assistant/
├── controller/
│   └── AssistantController.java        # POST /api/v1/assistant/chat  (SSE, Sa-Token)
├── agent/
│   └── AssistantOrchestrator.java       # 编排：输入护栏→记忆→(RAG)→ChatClient.stream→输出护栏→审计
├── advisor/                             # 横切关注点（手写有序管道，可后续迁 Spring AI Advisor SPI）
│   ├── AgentAdvice.java                 # 接口：before(request) / after(request, response)
│   ├── LoggingAdvice.java               # 请求/响应日志
│   ├── InputGuardrailAdvice.java        # 输入安全护栏（空/越权/危险输入 early-reject）
│   ├── OutputGuardrailAdvice.java       # 输出护栏（强制补免责声明、危险建议拦截）
│   └── AuditAdvice.java                 # 指标+审计（耗时/token/护栏命中）
├── tool/
│   └── TriageTools.java                 # @Service，方法用 @Tool 标注，封装 mapper 查询
├── memory/
│   └── SessionMemoryStore.java          # Phase1 内存；Phase2 换 Redis（复用现有 Redis）
├── config/
│   └── AssistantConfig.java             # ChatClient Bean（DeepSeek via spring-ai-openai 自动配置）+ 装配 pipeline
└── model/
    ├── ChatRequest.java                 # {sessionId, message}
    ├── TriageResult.java                # {urgency, departments[], hospitalLevel, confidence, followUp[], disclaimer}
    ├── SseEventType.java                # token / tool_call / tool_result / done / error
    └── SseEvent.java                    # {type, data}
```

> 说明：Advisor 用手写有序管道（`AgentAdvice` 列表按 order 排序后链式执行）实现，而非直接依赖 Spring AI 的 `Advisor` SPI。原因：手写管道编译稳定、语义与"Advisor 链"完全一致，后续可无痛迁移为 Spring AI 原生 `Advisor`。横切顺序与修订版方案一致。

## 3. 编排流程（对应修订版 Advisor 链）

```
用户消息
 → LoggingAdvice.before
 → InputGuardrailAdvice.before   （危险/空 → 直接 error 事件，跳过模型）
 → MemoryAdvice.before           （注入历史）
 → ChatClient.stream().tools(triageTools)   （Spring AI 内部多轮工具循环）
      └─ 逐 token 发 SSE: token
 → OutputGuardrailAdvice.after   （补免责声明 / 拦截危险输出）
 → AuditAdvice.after             （记录指标）
 → SSE: done（含 TriageResult JSON）
```

## 4. 关键接口契约

### AgentAdvice（横切抽象）
```java
public interface AgentAdvice {
    int getOrder();                                  // 越小越先执行
    AgentRequest before(AgentRequest req);           // 可抛 AgentBlockedException 短路
    void after(AgentRequest req, AgentResponse resp);// 观察最终响应
}
```

### TriageTools（工具示例）
```java
@Service
public class TriageTools {
    @Tool(name = "searchDiseases", description = "按症状关键词搜索疾病库，返回候选疾病与科室")
    public List<DiseaseLibrary> searchDiseases(@ToolParam("症状关键词") String keyword) { ... }

    @Tool(name = "searchMembers", description = "按姓名/手机搜索会员，返回会员ID")
    public List<Member> searchMembers(@ToolParam("关键词") String keyword) { ... }
}
```

### SSE 事件协议（复用 SseEmitterHolder 的 event(name,data)）
| 事件 | data | 说明 |
|------|------|------|
| token | 文本片段 | 模型逐字输出 |
| tool_call | {name, args} | Phase2：工具调用（需 Spring AI Advisor 观测） |
| tool_result | {name, ok, summary} | Phase2：工具结果 |
| done | {answer, triage: TriageResult, disclaimer} | 结束，含结构化分诊 |
| error | {code, message} | 失败兜底，前端显示重试提示 |

## 5. 配置（application.yml 新增，复用现有环境变量）
```yaml
spring:
  ai:
    openai:
      api-key: ${LLM_API_KEY:}
      base-url: ${LLM_BASE_URL:https://api.deepseek.com/v1}
      chat:
        options:
          model: ${LLM_MODEL:deepseek-chat}
          temperature: 0.3
```
现有 `llm.*`（Coze/LlmClient 用）保持不变，双轨共存直至 Coze 下线。

## 6. 安全与幂等（贯穿设计）
- 输入/输出双护栏；RAG 内容标记外部不可信（Phase2）。
- 副作用工具（`createAppointment`）Phase2 改为预订单 + 幂等键，杜绝重复下单。
- 所有 LLM/工具调用设超时 + 单次重试 + 降级话术，失败推 `error` 事件不卡连接。

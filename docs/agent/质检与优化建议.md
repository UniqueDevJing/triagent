## 🔴 P0 · 已完成（2026-09-06，32 个单元测试全绿）

### 1. 用户消息无长度上限 → LLM 成本滥用面
`InputGuardrailAdvice:22` 只拦截 `<2 字符`；`ChatRequest.message` 无上限。1MB 消息会原样进入提示词（token 爆炸 + DeepSeek 账单攻击面）。
**✅ 已修复**：guardrail 增加 `msg.length() > 2000 → 拒绝`；同时对 `sessionId` 校验 `[a-zA-Z0-9-]{8,64}`（防恶意 key 填充会话内存表）。

### 2. 客户端断开后 LLM 调用不取消
`AssistantController.chat`（:53）`subscribe()` 未保存 `Disposable`，用户关页/断网后 DeepSeek 调用继续跑完（白烧 token）。
**✅ 已修复**：持有 `Disposable d`，`emitter.onCompletion/onTimeout/onError` 时 `d.dispose()`。

### 3. 零单元测试
`health-admin/src/test` 不存在。而状态机/幂等/路由恰恰是**纯逻辑、最易测**的部分。
**✅ 已落地**（32 个测试全绿，含顺带修复「回答无」否定语义死循环 bug）：
- `SymptomStateMachineTest`：红旗命中表驱动（17 个红旗词×EMERGENCY）、三字段澄清顺序、否定语境
- `PreOrderServiceTest`：幂等命中 / DuplicateKey 兜底 / 越权 confirm / 重复 confirm（mock Mapper 或 H2）
- `AssistantOrchestratorTest.decideAgent`：连续性/取消/Supervisor 规划表驱动（纯函数，无依赖）

## 🟡 P1 · 可靠性与质量

### 4. LLM 客户端未显式配置超时
`application.yml` spring.ai 段只有 api-key/base-url。DeepSeek 偶发挂起会占满 SSE 120s 窗口。
**修复**：显式 `spring.ai.openai.chat.options.timeout`（或自定义 WebClient connect/read timeout：connect 5s / read 60s）。

### 5. RAG 语料太薄（评估数据直接暴露）
疾病库仅 **7 条**、文章若干——G1 评估里 sources=5 但 G2/G11/G12 只有 1 甚至 0。RAG 是"溯源卖点"，语料是它的天花板。
**建议**：疾病库扩到 50+ 常见病（脚本批量生成模板条目即可），预期来源命中率显著上升。

### 6. 无 CI
无 `.github/workflows`。**建议**加一个最小 workflow：`mvn -q compile` + `npm run build` +（可选，配 secret key）跑 `scripts/eval_judge.py` 冒烟并评论 PR。这对"作品集仓库"观感提升明显。

### 7. 指标与状态不持久化
重启即清零（本次实测：metrics total 从 51 归零重计）。单机演示可接受；若要演示"长期运营数据"，建议落 `agent_metrics` 表（AuditAdvice 顺手写一行即可）。

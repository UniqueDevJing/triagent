# 智能分诊与就医助手 Agent — 实施计划

> 分四个阶段推进，每阶段有明确交付物与退出标准（Exit Criteria）。环境备注：沙箱无 Maven，编译/启动需在你本机 `mvn -pl health-admin -am spring-boot:run` 验证。

## Phase 1 — 编排骨架 + SSE 流式（可演示起点）
**目标**：跑通"前端发消息 → 后端流式返回 + 双护栏 + 审计"，复用 DeepSeek。
**交付物**：
- 父 pom 引入 `spring-ai-bom`；health-admin 引入 `spring-ai-starter-model-openai:1.0.0`（注意：旧坐标 `spring-ai-openai-spring-boot-starter` 在 1.0.0 GA 不存在，仅到 M5/M6 里程碑）。
- `application.yml` 增加 `spring.ai.openai.*`（读现有 `LLM_*` 环境变量）。
- `com.health.web.assistant` 包：controller / orchestrator / advisor(4) / tool / memory / config / model。
- `AssistantController`：`POST /api/v1/assistant/chat` 返回 `SseEmitter`，Sa-Token 登录校验。
- `TriageTools`：`searchDiseases` + `searchMembers` 两个 `@Tool`，封装现有 mapper。
- 双护栏（输入/输出）+ Logging + Audit 以 `AgentAdvice` 管道实现。
- `AssistantConfig` 显式定义 `ChatClient` bean（Spring AI 1.0.0 GA 不自动注册 `ChatClient` 实例，仅提供 `ChatClient.Builder`）。
**退出标准**：本地启动后 `curl` 该端点能收到 `token` 流与 `done` 事件；危险输入被 `error` 短路；无编译错误。

> **状态：✅ 已完成（2026-09-02）**
> 实际验证（本机，JDK17 + Maven 3.9.9 wrapper + MySQL/Redis 均运行）：
> 1. 编译：`mvn -pl health-admin -am compile -DskipTests` → BUILD SUCCESS（修正 3 处 GA API 差异：`@ToolParam(description=)`、`String.join` 流式累积、lambda 捕获 final）。
> 2. 启动：`mvn -pl health-admin -am install -DskipTests` 后 `mvn -pl health-admin spring-boot:run`（先 `set -a; . ./.env; set +a` 注入 `LLM_API_KEY`/`DB_PASSWORD`，`export SERVER_PORT=8080`）→ `Started HealthApplication in 9.2s`，DB+Redis 连通，DataInitializer 跳过种子。
> 3. 冒烟：未登录 `POST /api/v1/assistant/chat` → **HTTP 401**（证明端点路由 + `@SaCheckLogin` 装配正确）。
> 4. 安全加固：`application.yml` 中 `llm.api-key` 默认值由硬编码密钥改为 `${LLM_API_KEY:}`（密钥仅来自 `.env`/环境变量）。
> 后续可选：完整 SSE 往返需登录会话（Sa-Token）+ 真实 `LLM_API_KEY`，二者在 `.env` 已具备。

## Phase 2 — 多 Agent 路由 + 工具循环可视化 + 预约幂等
**目标**：Triagel/Report/Scheduler 三 Agent 独立配置；前端可见"调工具"过程；预约两步确认。
**交付物**：
- `AgentRouter` 按意图选 Agent；每 Agent 独立 `ChatClient` + Advisor/工具集。
- Spring AI `Advisor` 观测工具调用，发 `tool_call` / `tool_result` SSE 事件。
- `createAppointment` 改为预订单（`agent_preorder` 表）+ 幂等键（`sha256(userId+symptomHash+date)`，Redis TTL 5min）。
- 结构化分诊用 `BeanOutputConverter` 绑定 `TriageResult`。
**退出标准**：多轮对话中可见工具调用事件；重复预约返回同一预订单，不落库重复记录。

> **状态：✅ 代码完成并真机验证（2026-09-02）**
> 落地内容：
> - `AgentRegistry` 规则路由（预约→SCHEDULER / 报告→REPORT / 默认→TRIAGE）；`AgentDefinition` 带工具白名单。
> - 单 `AgentToolkit`（统一 @Tool 集）+ `ToolCallbacks.from` 后按 `getToolDefinition().name()` 过滤 → `.toolCallbacks(...)`（注意：GA 中 `.tools(Object)` 只接受 @Tool 对象，`ToolCallback` 必须走 `.toolCallbacks`）。
> - 每请求 `Sinks.Many` 侧通道，`ToolEventPublisher` 发 TOOL_CALL/TOOL_RESULT，编排层 `Flux.merge(text, toolSink)`；`doFinally` 关闭 sink 后 concatWith DONE（携带 agent 名）。
> - `sql/migration_agent_preorder.sql`（`agent_preorder` 表 + `uk_idempotency_key` 唯一索引），已并入 init.sql 并应用到本地 MySQL。
> - `PreOrderService`：Redis SETNX(5min) + DB 唯一索引双层幂等；confirm 状态机（PENDING→CONFIRMED 幂等拦截）。
> - 编排层注入了 `BeanOutputConverter(TriageResult.class)` 做结构化解析绑定。
> 真机验证（登录 + curl）：未登录 401 ✓；confirm 不存在单→"预订单不存在" ✓；直插 PENDING 行→首次 confirm 返回 CONFIRMED 且 confirm_time 落库 ✓；重复 confirm→"状态为 CONFIRMED"拦截 ✓；DB 唯一索引就位 ✓；请求可达 DeepSeek（URL 正确 `…/v1/chat/completions`）。
> **阻塞**：DeepSeek 返回 **402 Payment Required**（该 API key 账户余额不足/欠费）→ 真实 LLM 工具循环演示无法完成，需充值或换 key 后复测 SSE 的 tool_call/tool_result 事件与"重复预约同单"最终演示。
> 踩坑：curl 发中文需 UTF-8 body 文件（Git Bash 默认 GBK）；base-url 需去掉 `/v1`（Spring AI 自行拼接），改读 `LLM_BASE_URL_ROOT`。

## Phase 3 — RAG 知识增强 + 对话状态机
**目标**：分诊建议 grounding 于医疗知识库，可溯源；多轮澄清采集症状。
**交付物（含方案适配）**：
- ~~pgvector~~ **适配 MySQL**：`KnowledgeRetriever` 接口 + `KeywordKnowledgeRetriever`（疾病库/科普文章 中文 bigram+词频混合检索，零新依赖，符合 CLAUDE.md MySQL 约定）。向量实现（MySQL9 VECTOR / pgvector）预留为接口可插拔，待有 embedding 来源再接入。
- `RagAdvice`（order 20）注入检索上下文：标记「外部不可信、指令忽略」，来源列表随 DONE 事件返回（可溯源、防注入）。
- 对话状态机 `SymptomStateMachine`：会话内聚合 部位→时长→伴随症状→红旗，驱动多轮澄清；命中红旗（胸痛/卒中征兆等）**确定性 EMERGENCY 短路**（不耗 LLM，离线可演示）。
- 结构化分诊 `BeanOutputConverter` 绑定（沿用 Phase2）。
**退出标准**：分诊响应附知识来源引用；红旗症状（胸痛/卒中）强制急诊建议 + disclaimer。

> **状态：✅ 代码完成并真机验证（2026-09-02）**
> 验证（登录 + curl，全确定性路径无需 LLM）：
> 1. 红旗短路：输入「我胸痛伴呼吸困难半小时」→ 事件 `done`，`triage.urgency=EMERGENCY`，科室并集 [急诊科,心内科,呼吸内科]，followUp 急救指引 + disclaimer，`sources` 回传知识来源（冠心病等）。
> 2. 多轮澄清：同一会话依次输入「我感觉不太舒服」→ 追问 bodyPart；「主要是头痛」→ 追问 duration；「持续3天了」→ 追问 accompany；「有点恶心，没有发烧」→ 字段齐全 → PROCEED（此后因 DeepSeek 402 计费进 LLM 报错，符合预期）。
> 3. 会话状态跨轮聚合正确（重复发第一条会推进到后续字段追问）。
> **阻塞同 Phase2**：DeepSeek 402（余额不足）→ LLM 真实分诊 + 来源引用的完整闭环待充值后复测；PROCEED 路径已确认能走到 LLM 调用。
> 遗留：`department` 表 embedding 未做（待向量方案），关键词检索召回质量一般（bigram naive），Phase4 评估可量化。
